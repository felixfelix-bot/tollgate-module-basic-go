WHY PACKAGE_VERSION=v0.6.0-alpha5 (explicit override; the repo VERSION file is
NOT changed - the module PR #536 stays a pin fix)
  Measured on apk-tools 3.0.2 (this SDK image and the OpenWrt 25.12 router):
  `apk add <file.apk>` whose version EQUALS the installed one is a NO-OP and does
  NOT rewrite the payload (dependency-free control package: install, tamper,
  re-add the same file -> the tampered file survives, apk prints only
  "OK: N B in M packages"). A 0.6.0_alpha4-r0 artifact could therefore install
  "successfully" and leave the OLD portal bundle on the router.
  `apk version -t 0.6.0_alpha5-r0 0.6.0_alpha4-r0` = ">"  -> a real upgrade.
  `apk fix <file.apk>` is not a workaround: it rejects a file argument
  ("Package '...' not found").
  `apk del tollgate-wrt` is NOT a safe workaround either: measured dry run purges
  tollgate-wrt AND jq AND libc AND nodogsplash (the daemon was pulled in as a
  dependency), which would leave the portal unenforced.
  The deploy script therefore also verifies router-side that the INSTALLED
  bundle carries the #LN004 marker, and fails closed with a recovery recipe if it
  does not, so a silent no-op cannot be mistaken for success.
