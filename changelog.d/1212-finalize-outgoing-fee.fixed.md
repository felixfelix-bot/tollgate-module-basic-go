- **A reported fee can no longer be an arbitrary number, and truthful spend is never refused for exceeding the budget.** The `paid` transition recorded whatever `uint64` the caller passed as `ActualFeeMSat`. `outgoingCostLocked` counts that value for resolved sends, so one absurd fee refused every later `Prepare` for that wallet — a durable denial of the payment path, with the verify response as the natural source of an unbounded value. The recorded fee is now bounded by a plausibility ceiling of `AmountMSat + FeeReserveMSat`, which rejects sentinel and overflow values while still allowing a genuine over-reserve. The period budget deliberately does **not** veto this record: spend that already happened is a fact, and refusing to journal it understates real expense — which lets the next payment push actual spend past the limit. A reviewer counterexample pinned that trade-off: a verified principal 1000 / fee 102 against a 1101 budget must record 1102 and then refuse the next payment, not record 1100 and permit another.
